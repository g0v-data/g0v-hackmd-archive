### AI大綱

**CivicTalk 會議重點整理（2026‑10‑21 19:19‑19:58）**

---

## 1. 目前使用痛點
- **表單與素材上傳流程繁瑣**：必須不斷複製/貼上，使用者體驗不佳。  
- **缺乏自動化**：希望透過 **「Sign‑in with ChatGPT / Claude / Gemini」** 直接串接 API，讓系統自動產生正、反方論點、摘要與標籤（tag）。

---

## 2. 兩大使用情境

| 情境 | 特徵 | 主要需求 |
|------|------|----------|
| **A. 二元（是／否）議題** | 有明確的「贊成 / 反對 / 中立」立場 | ① 快速標記立場 ② AI 整理正反方論點 |
| **B. 開放式（審議／申論）議題** | 無明確是非答案，只求多元觀點（例：世代正義） | ① 靈活的 Tag 系統 ② 允許使用者自行標記或由 AI 建議 |

&gt; 兩者在 **UI/UX、標籤設計、結果呈現** 上皆需差異化處理。

---

## 3. Tag 設計建議

1. **二元議題**  
   - 預設三種標籤：**贊成 / 反對 / 中立**。  
2. **開放式議題**  
   - 允許使用者自行建立*彈性 Tag*（如「老人福利」「財政負擔」「世代正義」），不受三種固定選項限制。  
   - Tag 可由 **AI 自動從素材摘要產生**，或由管理員／原 PO 預先設定選項供使用者挑選。  
3. **層級結構**  
   - **第一層**：議題的類別（例：國際 / 台灣 / 警政 / 教育）。  
   - **第二層**：針對每個立場的細部 Tag（若議題為二元則省略）。  

&gt; Tag 的彈性設計同時提升 **搜尋、分類** 與 **AI 整理** 的效率。

---

## 4. AI 介入的範圍與成本

| 功能 | 可自動化程度 | 成本模型 |
|------|--------------|----------|
| **素材摘要與 Tag 產生** | 中等（依素材品質） | **用量付費**（token 計算） |
| **正反方議點自動整理** | 高（依 Prompt 設計） | 用量付費 + 可能的付費 API（如 OpenRouter、Cloudflare） |
| **產出審議手冊 (PDF/Markdown)** | 高（生成 Prompt → 交給外部 LLM） | 只需一次性複製貼上操作，成本極低 |
| **全站內自動化** | 低效益/成本比不佳 | 目前建議保留人工流程，尤其是 Tag 精細度要求高時 |

&gt; 大部分 AI 服務採 **「使用量付費」**（輸入/輸出 token 每百萬 0.XX 美金），但可透過 **一次性產出 Prompt** 交給外部 LLM，減少站內計算。

---

## 5. 產品開發優先順序

1. **優化審議大會前置作業**  
   - 聚焦「資料蒐集 → 正反方整理 → 立場圖」的自動化。  
   - 目標使用者：**審議會管理者（如 Peter）**，非一般志願者。  
2. **彈性 Tag 系統**  
   - 先在 UI 中加入「二元 vs 開放」切換，依類型呈現不同標籤選項。  
   - 允許管理員/原 PO 先行設定可選 Tag，AI 只負責建議。  
3. **Prompt 輸出功能**  
   - 產出 **opinion.md** 或 **PDF 手冊 Prompt**，使用者點擊「複製」後貼至 ChatGPT 等外部平台完成高品質文件生成。  
4. **結構化立場地圖（可選）**  
   - 以 Polis 類似的二維分群圖呈現，作為可視化選項，非必須功能，可視需求與預算再決定是否開發。

---

## 6. 預算與 API 估算

- **事實查核**：約 **0.05 美金/次**（示範用）。  

&gt; 若需求超出此範圍，可考慮 **付費訂閱**（固定月費、上限流量）或 **自行部署開源模型**。

---

## 7. 會議結論

- **先聚焦審議大會的前置資料蒐集與自動化**，在此基礎上逐步擴展至一般大眾使用。  
- **Tag 系統** 必須同時支援 **固定二元標籤** 與 **彈性多層 Tag**，以適應不同議題類型。  
- **AI 自動化** 僅在成本效益明顯的情境下導入；現階段以 **外部 LLM（Prompt 輸出）** 為主要方式，減少站內計算與維護負擔。  
- **預算可控**：以使用量付費模型估算，確保每次審議會的 AI 成本不超過百美元。
